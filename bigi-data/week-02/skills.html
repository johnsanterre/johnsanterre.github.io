Lectures

Colleges

Four short lectures teach the four habits of the week. Each one works an example from the notebook and leaves one for you to finish.

Why reading comes before writing

Waarom lezen vóór schrijven komt

An AI assistant now writes most first drafts of code. The person at the keyboard no longer types every line from memory. That person must still read every line the assistant returns and say what it does, because last week showed that code can run and still give a wrong answer. Reading is how you tell working code from right code.

Een AI-assistent schrijft tegenwoordig de meeste eerste versies van code. Wie achter het toetsenbord zit, typt niet langer elke regel uit het hoofd. Die persoon moet nog steeds elke regel lezen die de assistent teruggeeft en kunnen zeggen wat hij doet, want vorige week bleek dat code kan draaien en toch een fout antwoord kan geven. Door te lezen onderscheid je code die werkt van code die klopt.

Reading code follows its own order. You read for the shape first, then you follow one value through the program, and then you check closely the few lines that carry the answer.

Code lezen volgt een eigen volgorde. Je leest eerst voor de vorm, dan volg je één waarde door het programma, en daarna controleer je nauwkeurig de paar regels die het antwoord dragen.

Predict, then run

Eerst voorspellen, dan uitvoeren

Before you run a cell, say what it will print. The prediction can be wrong, and it still does its work. A reader who predicted the output notices when the output is strange, while a reader who made no prediction accepts whatever appears. The notebook asks for a prediction before most cells, and one CHECK tests a prediction you write down.

Zeg wat een cel zal afdrukken voordat je hem uitvoert. De voorspelling mag fout zijn en doet toch haar werk. Een lezer die de uitvoer voorspelde, merkt het op wanneer de uitvoer vreemd is, terwijl een lezer zonder voorspelling alles accepteert wat verschijnt. Het notebook vraagt voor de meeste cellen om een voorspelling, en één CHECK toetst een voorspelling die je opschrijft.

Every name has a unit

Elke naam heeft een eenheid

A name in code, such as kg or price_per_kg, holds a number, and almost every number in real work has a unit. Write the unit next to each name as a comment, then multiply the units the way the code multiplies the values.

Een naam in code, zoals kg of price_per_kg, bevat een getal, en bijna elk getal in echt werk heeft een eenheid. Schrijf de eenheid als opmerking naast elke naam, en vermenigvuldig dan de eenheden zoals de code de waarden vermenigvuldigt.

  • Kilograms per crate times dollars per kilogram gives dollars per crate. The kilograms cancel and leave a unit with a clear meaning.Kilo per krat maal dollar per kilo geeft dollar per krat. De kilo's vallen weg, en het resultaat heeft een duidelijke betekenis.
  • Crates times dollars per kilogram gives a unit that means nothing. A formula that produces it is wrong, however reasonable its output looks.Kratten maal dollar per kilo geeft een eenheid die niets betekent. Een formule die zo'n eenheid oplevert, is fout, hoe redelijk de uitkomst er ook uitziet.

Read for shape before detail

Lees voor de vorm vóór de details

A program can run to hundreds of lines, and line one is rarely the place to start. First answer three questions.

Een programma kan honderden regels lang zijn, en regel één is zelden de plek om te beginnen. Beantwoord eerst drie vragen.

  • What goes in? Find where the data comes from: a file, a web address, or numbers the program makes itself.Wat gaat erin? Zoek waar de data vandaan komt: een bestand, een webadres, of getallen die het programma zelf maakt.
  • What comes out? Find what the program prints, saves or returns.Wat komt eruit? Zoek wat het programma afdrukt, opslaat of teruggeeft.
  • What are the main steps? Find the functions, the named blocks that start with def. A well-named function states its purpose before you read its body.Wat zijn de hoofdstappen? Zoek de functies, de blokken met een naam die met def beginnen. Een functie met een goede naam zegt waarvoor hij dient voordat je de inhoud leest.

Then decide what you can leave unread. If your question is how many kilograms each farm delivered, the code that makes the practice data can wait, and the line that multiplies crates by kilograms per crate deserves a close look. A good reader chooses what to skip and can say why.

Beslis daarna wat je ongelezen kunt laten. Als je vraag is hoeveel kilo elke boerderij leverde, kan de code die de oefendata maakt wachten, en verdient de regel die kratten met kilo per krat vermenigvuldigt een nauwkeurige blik. Een goede lezer kiest wat hij overslaat en kan zeggen waarom.

Find where it starts

Zoek waar het begint

A def block defines a function and stops there. Python learns the steps and waits until a line calls the function by name. The entry point of a program is the first line that does real work, usually the first line outside every def block. In a notebook, the work happens in the order in which you run the cells.

Een def-blok definieert een functie en houdt daar op. Python leert de stappen en wacht tot een regel de functie bij naam aanroept. Het startpunt van een programma is de eerste regel die echt werk doet, meestal de eerste regel buiten elk def-blok. In een notebook gebeurt het werk in de volgorde waarin je de cellen uitvoert.

A nested call such as add_weight(make_deliveries(seed=11)) reads from the inside out. The inner function runs first, and its result becomes the input of the outer one.

Een geneste aanroep zoals add_weight(make_deliveries(seed=11)) lees je van binnen naar buiten. De binnenste functie draait eerst, en het resultaat wordt de invoer van de buitenste.

Follow one value

Volg één waarde

Reading for shape tells you what a program is meant to do. Following one value tells you what it does. Pick one row, such as one farm in one week, and print it after each step. In the notebook, one delivery of 22 crates becomes 264 kilograms after the second step, and the farm's total then matches the sum of its rows. A printed value at each step replaces a belief about the code with an observation.

Lezen voor de vorm vertelt je wat een programma hoort te doen. Eén waarde volgen vertelt je wat het doet. Kies één rij, zoals één boerderij in één week, en druk die na elke stap af. In het notebook wordt één levering van 22 kratten na de tweede stap 264 kilo, en daarna komt het totaal van de boerderij overeen met de som van haar rijen. Een afgedrukte waarde bij elke stap vervangt een vermoeden over de code door een waarneming.

Loops and running totals

Lussen en lopende totalen

A for loop repeats its indented lines once for each item in a list. A running total starts at zero and grows by one item on each turn. Loops show every step, which makes them easy to trace and slow to read. An AI assistant will often offer a shorter version in one line of pandas, and that version needs one check against the long one before you rely on it.

Een for-lus herhaalt de ingesprongen regels één keer voor elk item in een lijst. Een lopend totaal begint bij nul en groeit bij elke ronde met één item. Lussen tonen elke stap, waardoor ze makkelijk te volgen en traag te lezen zijn. Een AI-assistent biedt vaak een kortere versie aan in één regel pandas, en die versie heeft één controle tegen de lange versie nodig voordat je erop vertrouwt.

When the AI is wrong

Wanneer de AI zich vergist

In the notebook, an AI assistant was asked for each farm's revenue in dollars. Its code ran without an error and reported a total of 1,641.00 dollars. Revenue computed from kilograms comes to 21,241.80 dollars. The AI's answer was too small by a factor of 12.9.

In het notebook werd een AI-assistent gevraagd naar de omzet van elke boerderij in dollars. De code draaide zonder fout en gaf een totaal van 1.641,00 dollar. De omzet berekend uit kilo's komt uit op 21.241,80 dollar. Het antwoord van de AI was te klein met een factor 12,9.

The AI multiplied crates by the price per kilogram and named the result revenue_usd. Crates times dollars per kilogram leaves kilograms in the unit. The formula was wrong before it ran. The error also changed the ranking. The AI's code put farm D first, while farm C earned the most. Writing the unit of each column next to the formula catches this mistake without running anything.

De AI vermenigvuldigde kratten met de prijs per kilo en noemde het resultaat revenue_usd. Kratten maal dollar per kilo laat kilo's in de eenheid staan, dus de formule was al fout voordat hij draaide. De fout veranderde ook de rangorde. De code van de AI zette boerderij D bovenaan, terwijl boerderij C het meest verdiende. Wie de eenheid van elke kolom naast de formule schrijft, vindt deze fout zonder iets uit te voeren.

Write the note for the next reader

Schrijf de notitie voor de volgende lezer

Someone else will read every program you finish, and often that someone is you a month later. Three sentences get that reader started: what the program takes in, what it produces, and where it starts. A fourth sentence names any trap you found. The note takes a few minutes and spares the next reader the search you made.

Iemand anders leest elk programma dat je afmaakt, en vaak ben jij dat zelf een maand later. Drie zinnen helpen die lezer op weg: wat het programma binnenkrijgt, wat het oplevert, en waar het begint. Een vierde zin noemt elke valkuil die je vond. De notitie kost een paar minuten en bespaart de volgende lezer de zoektocht die jij maakte.

QuestionVraag 1

You run a cell that holds only a def block, and nothing is printed. What happened?

Je voert een cel uit met alleen een def-blok, en er wordt niets afgedrukt. Wat is er gebeurd?

  2. Python learned the function, and nothing in it runs until a line calls it.Python leerde de functie, en niets erin draait totdat een regel hem aanroept.
  3. The cell failed without an error message.De cel mislukte zonder foutmelding.

The second answer is right. A def block defines a function. The work happens only when a line calls the function by name, so the entry point of a program is the first line outside the definitions.

Two ways to watch a program run

Twee manieren om een programma te volgen

The notebook traces values with print. A second tool, the debugger, runs a program one line at a time and shows every name and its value as the line runs. The two tools answer different questions. A print line records one value at one moment. The record stays in the notebook as evidence for the next reader. A debugger shows everything at every step. It helps most when a printed value surprises you and the cause is not yet clear. It also leaves nothing behind once you close it.

Het notebook volgt waarden met print. Een tweede hulpmiddel, de debugger, voert een programma regel voor regel uit en toont elke naam met zijn waarde terwijl de regel draait. De twee hulpmiddelen beantwoorden verschillende vragen. Een print-regel legt één waarde op één moment vast, en dat verslag blijft in het notebook staan als bewijs voor de volgende lezer. Een debugger toont alles bij elke stap. Dat helpt wanneer een afgedrukte waarde je verrast en de oorzaak nog niet duidelijk is, en er blijft niets van over zodra je hem sluit.

A sound order of work is to print first and step through second. Print the value at the end of each function, as the notebook does for farm C. Where a printed value differs from your prediction, the fault lies between that print and the one before it. Step through that stretch alone. Then write what you found as a comment, because the debugger keeps no record once the session ends.

Een goede werkvolgorde is eerst afdrukken en daarna stap voor stap gaan. Druk de waarde af aan het eind van elke functie, zoals het notebook doet voor boerderij C. Waar een afgedrukte waarde verschilt van je voorspelling, zit de fout tussen die print en de vorige. Loop alleen dat stuk stap voor stap door, en schrijf wat je vond op als opmerking, zodat het bewijs de sessie overleeft.

Functions that call themselves

Functies die zichzelf aanroepen

Some functions solve a problem by handing a smaller piece of it to a new call of themselves. Such a function is recursive. To read one, find its stopping rule first: the line that returns an answer without calling the function again. Then follow one input and write down the value each call receives, until a call reaches the stopping rule. The answers then travel back up the chain, and each call adds its own part on the way.

Sommige functies lossen een probleem op door een kleiner deel ervan door te geven aan een nieuwe aanroep van zichzelf. Zo'n functie is recursief. Zoek bij het lezen eerst de stopregel: de regel die een antwoord teruggeeft zonder de functie opnieuw aan te roepen. Volg daarna één invoer en schrijf de waarde op die elke aanroep ontvangt, totdat een aanroep de stopregel bereikt. De antwoorden gaan dan de reeks weer op, en elke aanroep telt onderweg zijn eigen deel erbij op.

The question that matters most is whether every chain of calls reaches the stopping rule. A rule that tests for exact equality, such as a load of exactly zero, stops only for inputs that reach that exact value. Every other input runs past it, and the calls continue until Python gives up with an error. Units help here too. A load that shrinks by a fixed amount at each call reaches exactly zero only when that amount divides it exactly.

De vraag die het meest telt, is of elke reeks aanroepen de stopregel bereikt. Een regel die op precieze gelijkheid toetst, zoals een lading van precies nul, stopt alleen bij invoer die op die waarde uitkomt. Elke andere invoer schiet erlangs, en de aanroepen gaan door totdat Python het opgeeft met een fout. Ook hier helpen eenheden, want een lading die bij elke aanroep met een vaste hoeveelheid krimpt, komt alleen op nul uit als die hoeveelheid er precies in past.

Een moeilijkere opdracht

You trace the calls for one farm by hand, count the trips for every farm, and decide whether the AI's version ever stops before you test it. A CHECK cell confirms all three answers.

Onderdeel 12 en 13 van het notebook bevatten één moeilijkere opdracht. Een functie telt de vrachtwagenritten die nodig zijn om de kilo's van elke boerderij te vervoeren door zichzelf aan te roepen, en een AI-assistent biedt een eenvoudigere stopregel aan. Je volgt de aanroepen voor één boerderij met de hand, telt de ritten voor elke boerderij, en beslist of de versie van de AI ooit stopt voordat je het test.
