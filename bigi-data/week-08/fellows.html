Fellows' session guide, week 8

Lesgids voor fellows, week 8

This guide is for the teaching fellows. It sets the goal of the week, the plan for each workshop, what to look for in the studio, and how to run the Friday review, which also closes month 2.

Deze gids is voor de fellows die lesgeven. Hij beschrijft het doel van de week, het plan voor elke workshop, waar je in de studio op let, en hoe je de vrijdagbespreking leidt, die ook maand 2 afsluit.

The goal of the week

Het doel van de week

By Friday, every student can keep a project in a repository, write commits a stranger can read, pull before pushing, resolve a conflict, and hold back a command until they know what it will erase. Each team leaves the week with a public repository that answers project 8, a README another team has tested, and a note a ministry official could use. A Surinamese organisation can then pick up the team's work and check it without the team in the room.

Op vrijdag kan elke student een project in een repository bijhouden, commits schrijven die een buitenstaander kan lezen, pullen voordat hij pusht, een conflict oplossen, en een opdracht tegenhouden totdat hij weet wat die zal wissen. Elk team sluit de week af met een openbare repository die project 8 beantwoordt, een README die een ander team heeft getest, en een notitie waar een ambtenaar van een ministerie iets mee kan. Een Surinaamse organisatie kan dan het werk van het team oppakken en controleren zonder dat het team erbij is.

Before Monday

Vóór maandag

  • Check that every student can create a GitHub account and complete two-factor authentication, and remind them to keep the recovery codes somewhere safe.Controleer dat elke student een GitHub-account kan maken en tweestapsverificatie kan afronden, en herinner ze eraan de herstelcodes op een veilige plek te bewaren.
  • Decide where the team repositories live. The simplest setup has each team's builder own the repository and add the other three as collaborators. A student who prefers not to show their full name can use a GitHub username that does not contain it.Bepaal waar de repositories van de teams staan. De eenvoudigste opzet is dat de bouwer van elk team de repository bezit en de andere drie als collaborators toevoegt. Een student die liever niet zijn volledige naam laat zien, kan een GitHub-gebruikersnaam kiezen zonder die naam.
  • Run both notebooks yourself from a fresh Colab session, confirm that git runs there, and read the solution notebook you received separately.Draai beide notebooks zelf in een nieuwe Colab-sessie, controleer dat git daar werkt, en lees het oplossingsnotebook dat je apart hebt ontvangen.
  • Prepare a practice repository on GitHub with a README line that two people can edit on Wednesday.Bereid een oefenrepository op GitHub voor met een README-regel die twee mensen op woensdag kunnen aanpassen.

The four workshops

De vier workshops

Monday: snapshots and the first repository (2 hours)Maandag: momentopnamen en de eerste repository (2 uur)

  • 15 minutes. Show a folder of copies (report, report_v2, report_final) and ask the room what changed between two of them and why. Nobody can answer from the files alone.15 minuten. Laat een map met kopieën zien (rapport, rapport_v2, rapport_definitief) en vraag de zaal wat er tussen twee ervan veranderde en waarom. Niemand kan dat uit de bestanden alleen halen.
  • 25 minutes. Every student signs in to GitHub, turns on two-factor authentication and sets the private noreply email address.25 minuten. Elke student logt in op GitHub, zet tweestapsverificatie aan en stelt het privé noreply-e-mailadres in.
  • 40 minutes. Every student makes a repository in the browser, writes a README, uploads one file and makes three commits with subjects that follow the rules.40 minuten. Elke student maakt een repository in de browser, schrijft een README, uploadt één bestand en maakt drie commits met onderwerpregels die de regels volgen.
  • 40 minutes. Open the history of a large public project, such as the Python language at github.com/python/cpython, and read it with the room: the newest commit, the oldest commit you can reach, and the history of one file.40 minuten. Open de geschiedenis van een groot openbaar project, zoals de taal Python op github.com/python/cpython, en lees die met de zaal: de nieuwste commit, de oudste commit die je kunt bereiken, en de geschiedenis van één bestand.

Tuesday: the command line and messages that say why (2 hours)Dinsdag: de opdrachtregel en berichten die zeggen waarom (2 uur)

  • 20 minutes. Draw the four places on the board and walk one file through them.20 minuten. Teken de vier plekken op het bord en loop met één bestand langs alle vier.
  • 40 minutes. Run sections 2 to 6 of the skills notebook live. Before each cell, the room predicts what git status will say.40 minuten. Draai sectie 2 tot en met 6 van het vaardighedennotebook live. Vóór elke cel voorspelt de zaal wat git status zal zeggen.
  • 40 minutes. Put ten weak commit subjects on the screen. Pairs rewrite them. The room then votes on which rewrites a stranger would understand.40 minuten. Zet tien zwakke onderwerpregels op het scherm. Tweetallen herschrijven ze, en de zaal stemt over welke versies een buitenstaander zou begrijpen.
  • 20 minutes. Show three diffs, and have students translate each hunk header into plain words.20 minuten. Laat drie diffs zien, en laat studenten elke hunk-header in gewone woorden vertalen.

Wednesday: working as a team (2 hours)Woensdag: werken als team (2 uur)

  • 20 minutes. Explain collaborators and forks. The builder of each team creates the project 8 repository and adds the other three.20 minuten. Leg collaborators en forks uit. De bouwer van elk team maakt de repository voor project 8 en voegt de andere drie toe.
  • 40 minutes. Cause a conflict on purpose. Pairs edit the same README line in the practice repository on two branches and open two pull requests. They merge one and resolve the other in the browser.40 minuten. Veroorzaak met opzet een conflict. Tweetallen passen dezelfde README-regel in de oefenrepository aan op twee branches en openen twee pull requests. Ze mergen er één en lossen de andere op in de browser.
  • 40 minutes. Each student makes one change on a branch, opens a pull request with a description of what changed and why, and reviews a teammate's pull request with a comment on one line.40 minuten. Elke student maakt één wijziging op een branch, opent een pull request met een beschrijving van wat er veranderde en waarom, en beoordeelt de pull request van een teamgenoot met een opmerking bij één regel.
  • 20 minutes. Each pair says what its conflict was and why its resolution is right.20 minuten. Elk tweetal zegt wat het conflict was en waarom de oplossing klopt.

Thursday: what never goes in a repository (2 hours)Donderdag: wat nooit in een repository komt (2 uur)

  • 20 minutes. Go through the four kinds of file that never go in, and show the output of section 12 of the skills notebook, where a deleted password stays readable.20 minuten. Bespreek de vier soorten bestanden die er nooit in komen, en laat de uitvoer van sectie 12 van het vaardighedennotebook zien, waar een verwijderd wachtwoord leesbaar blijft.
  • 30 minutes. Paste a rejected-push error into an AI assistant and read its answer aloud. The room judges each suggested command against the list before anyone runs it. Repeat with the question of how to save all your work and share it.30 minuten. Plak een foutmelding van een geweigerde push in een AI-assistent en lees het antwoord hardop voor. De zaal beoordeelt elke voorgestelde opdracht aan de hand van de lijst voordat iemand hem uitvoert. Herhaal dat met de vraag hoe je al je werk opslaat en deelt.
  • 40 minutes. Each team hands its draft README to another team, which tries to follow it cold and notes every place it had to guess.40 minuten. Elk team geeft zijn concept-README aan een ander team, dat hem zonder uitleg probeert te volgen en elke plek noteert waar het moest gokken.
  • 30 minutes. Teams write their .gitignore and read their repository's history for anything that should not be there.30 minuten. Teams schrijven hun .gitignore en lezen de geschiedenis van hun repository na op alles wat er niet in hoort.

In the studio

In de studio

Visit every team twice a day. Ask the same three questions each time, so the teams learn to ask them of themselves.

Bezoek elk team twee keer per dag. Stel elke keer dezelfde drie vragen, zodat de teams leren die vragen aan zichzelf te stellen.

  • Show me your last three commit subjects. What does each one say changed?Laat me je laatste drie onderwerpregels zien. Wat zegt elke regel dat er veranderde?
  • Who made the last commit, and did that person pull first?Wie maakte de laatste commit, en heeft die persoon eerst gepulld?
  • What would the ministry official do differently after reading your note?Wat zou de ambtenaar van het ministerie anders doen na het lezen van jullie notitie?

What to watch for this week

Waar je deze week op let

  • Teams that drop the missing years before they compute one-year changes. A rise measured across a gap of several years then looks like the largest one-year rise, and task 6 exists to catch it.Teams die de ontbrekende jaren weglaten voordat ze veranderingen per jaar berekenen. Een stijging over een gat van meerdere jaren lijkt dan de grootste stijging in één jaar, en opdracht 6 is er om dat te vangen.
  • Teams that fill the years with no value by drawing a line across them or by inventing values. The chart, the README and the note must show that the table has nothing there.Teams die de jaren zonder waarde opvullen door er een lijn overheen te trekken of door waarden te verzinnen. De grafiek, de README en de notitie moeten laten zien dat de tabel daar niets heeft.
  • Teams that read mobile subscriptions per 100 people as the share of people with a phone. One person can hold several subscriptions, which lets the series pass 100.Teams die mobiele abonnementen per 100 inwoners lezen als het aandeel mensen met een telefoon. Eén persoon kan meerdere abonnementen hebben, dus de reeks kan boven 100 komen.
  • Teams that explain the fast growth across the missing years, or the sharp fall in the mobile series, without a source. The table records the change and not its cause.Teams die de snelle groei over de ontbrekende jaren, of de sterke daling in de mobiele reeks, verklaren zonder bron. De tabel legt de verandering vast en niet de oorzaak.
  • Teams that repeat the AI's number for a year the table does not cover, without a source they opened.Teams die het getal van de AI herhalen voor een jaar dat de tabel niet dekt, zonder een bron die ze zelf hebben geopend.
  • AI-suggested commands that a builder runs before the AI checker has seen them. A force push in a team repository is the one to stop.Opdrachten van de AI die een bouwer uitvoert voordat de AI-controleur ze heeft gezien. Een force push in een teamrepository is degene die je tegenhoudt.
  • Personal email addresses in public commits. Students should commit with GitHub's noreply address.Persoonlijke e-mailadressen in openbare commits. Studenten horen te committen met het noreply-adres van GitHub.

The Friday review

De vrijdagbespreking

  • Before the review. Each team receives another team's repository address and has 30 minutes to follow its README cold, running the notebook from the repository alone. They write down every place they had to guess.Vóór de bespreking. Elk team krijgt het repository-adres van een ander team en heeft 30 minuten om de README zonder uitleg te volgen en het notebook alleen vanuit de repository te draaien. Ze schrijven elke plek op waar ze moesten gokken.
  • Each team. Five minutes to present the note as if to the ministry official, then five minutes of questions, starting with the guesses from the team that tested its README. A fellow asks the last question.Elk team. Vijf minuten om de notitie te presenteren alsof de ambtenaar van het ministerie in de zaal zit, daarna vijf minuten vragen, te beginnen met de gokplekken van het team dat de README testte. Een fellow stelt de laatste vraag.
  • After the presentations. The room lists every AI claim and every AI-suggested command that was wrong this week, and how each one was caught.Na de presentaties. De zaal maakt een lijst van elke foute bewering en elke foute opdracht van de AI van deze week, en hoe die werd ontdekt.
  • The look back at month 2. For 30 minutes, each student names one habit from the month they now use without thinking and one they still skip. Fellows note the skipped habits for month 3.De terugblik op maand 2. Gedurende 30 minuten noemt elke student één gewoonte uit de maand die hij nu vanzelf toepast en één die hij nog overslaat. Fellows noteren de overgeslagen gewoonten voor maand 3.
  • To close. Announce next week's roles.Ter afsluiting. Maak de rollen voor volgende week bekend.
