After part 1: A notebook is a workbenchNa deel 1: Een notebook is een werkbank

QuestionVraag 1

You open a notebook fresh and press play on a cell near the bottom that prints a name defined in a cell near the top. What happens?

Je opent een notebook opnieuw en drukt op afspelen bij een cel onderaan die een naam afdrukt die in een cel bovenaan is gedefinieerd. Wat gebeurt er?

This trusts the page order, which the notebook never reads; it remembers what ran, not what is written.Dit vertrouwt op de volgorde op de pagina, en die leest het notebook nooit; het onthoudt wat is uitgevoerd, niet wat er staat.

Correct. The notebook remembers what ran, not what is written, and nothing has run yet, so the name is not in memory.Juist. Het notebook onthoudt wat is uitgevoerd, niet wat er staat, en er is nog niets uitgevoerd, dus de naam zit niet in het geheugen.

This describes restart and run all, which you must ask for; a single play button runs one cell only.Dit beschrijft herstarten en alles uitvoeren, waar je zelf om moet vragen; één afspeelknop voert maar één cel uit.

QuestionVraag 2

You change a cell from shop_name = "the corner shop" to shop_name = "the market stall" but do not run it. The next cell prints shop_name. What appears?

Je verandert een cel van shop_name = "the corner shop" in shop_name = "the market stall" maar voert hem niet uit. De volgende cel drukt shop_name af. Wat verschijnt er?

This assumes the notebook reads the page, which it does not; the memory still holds the version that ran.Dit gaat ervan uit dat het notebook de pagina leest, en dat doet het niet; het geheugen houdt de versie vast die is uitgevoerd.

Correct. Editing changes the page and nothing else; the memory still holds the version that ran.Juist. Bewerken verandert alleen de pagina; het geheugen houdt de versie vast die is uitgevoerd.

Nothing is broken; the notebook does not even know the text changed.Er is niets kapot; het notebook weet niet eens dat de tekst is veranderd.

QuestionVraag 3

What does restart and run all do?

Wat doet herstarten en alles uitvoeren?

The page is never touched; only the memory is cleared.De pagina wordt nooit aangeraakt; alleen het geheugen wordt gewist.

Correct, and it is the finishing habit of this part: if the notebook runs clean from the top, the page and the memory agree.Juist, en dit is de afsluitende gewoonte van dit deel: als het notebook schoon van boven naar beneden draait, komen pagina en geheugen overeen.

No notebook does this; it cannot know which cells drifted, which is exactly why it runs them all.Geen enkel notebook doet dit; het kan niet weten welke cellen zijn afgedreven, en daarom voert het ze juist allemaal uit.

QuestionVraag 4

Where does the code run when you press play in Colab, and where does the output appear?

Waar draait de code als je in Colab op afspelen drukt, en waar verschijnt de uitvoer?

This is the picture of a script on your own computer. In Colab nothing is installed on your machine and nothing on it can break.Dit is het beeld van een script op je eigen computer. In Colab wordt niets op je eigen machine geïnstalleerd en kan er niets kapot.

Correct. Nothing is installed on your machine and nothing on it can break; only the results travel back to your browser, under the cell that made them.Juist. Er wordt niets op je eigen machine geïnstalleerd en er kan niets kapot; alleen de resultaten reizen terug naar je browser, onder de cel die ze maakte.

Output is shown on the page, not written to a file, unless your code asks for that.Uitvoer wordt op de pagina getoond en niet naar een bestand geschreven, tenzij je code daarom vraagt.

QuestionVraag 5

Je komt de volgende ochtend terug bij een Colab-notebook. De pagina is precies zoals je hem achterliet. Wat is er verder nog?

This treats the memory as if it were saved with the page, which it never is. The data-center computer was lent to you for the session and has been taken back, memory included.Dit behandelt het geheugen alsof het met de pagina wordt opgeslagen, en dat gebeurt nooit. De computer in het datacenter was voor de sessie aan je uitgeleend en is teruggenomen, geheugen en al.

Correct. The data-center computer was lent to you for the session and has been taken back, memory included, so you start with restart and run all.Juist. De computer in het datacenter was voor de sessie aan je uitgeleend en is teruggenomen, geheugen en al, dus je begint met herstarten en alles uitvoeren.

This confuses old output text, which may still show on the page, with results in memory; the text is only a picture of what once ran.Dit verwart oude uitvoertekst, die nog op de pagina kan staan, met resultaten in het geheugen; die tekst is alleen een afbeelding van wat eens is uitgevoerd.

Correct. The request never said whether you wanted a total or a daily figure, units or money, so the assistant chose for you.Juist. De vraag zei niet of je een totaal of een dagcijfer wilde, stuks of geld, dus koos de assistent voor jou.

Which four things does a good request for code carry?

Correct: data, shape, unit and problems, every time.Juist: data, vorm, eenheid en problemen, elke keer.

These are things that do not change what the code computes.Dit zijn dingen die niet veranderen wat de code berekent.

This is the belief this part took apart: whatever you leave out, the assistant decides for you, without telling you.Dit is de overtuiging die dit deel heeft ontleed: wat je weglaat, beslist de assistent voor jou, zonder het te zeggen.

QuestionVraag 3

The request "Give me the average number of units sold per day" returned code with fillna(0) in it. What does that tell you about the request?

De vraag "Geef me het gemiddelde aantal verkochte stuks per dag" gaf code terug met fillna(0) erin. Wat zegt dat over de vraag?

Correct. The request named the column, the shape and the unit, but not the treatment of missing values, so the assistant chose zero and said so only inside the code.Juist. De vraag noemde de kolom, de vorm en de eenheid, maar niet de behandeling van ontbrekende waarden, dus koos de assistent voor nul en zei dat alleen in de code.

The column name was read correctly; the choice was about the gaps, not the name.De kolomnaam werd goed gelezen; de keuze ging over de gaten, niet over de naam.

pandas computes the average with or without the count; the line is there for you, not for pandas.pandas berekent het gemiddelde met of zonder het aantal; de regel is er voor jou, niet voor pandas.

The extra line is there for checking, not for show.De extra regel is er om te controleren, niet om indruk te maken.

QuestionVraag 5

An assistant returns twenty lines of code you cannot follow. What do you do?

Een assistent geeft twintig regels code terug die je niet kunt volgen. Wat doe je?

This throws away a fast colleague; the assistant can do the typing, and your job is to understand and check what it typed.Dit gooit een snelle collega weg; de assistent kan het typwerk doen, en jouw taak is te begrijpen en te controleren wat hij typte.

Correct: ask again, differently, and never run code you cannot explain.Juist: vraag opnieuw, anders, en voer nooit code uit die je niet kunt uitleggen.

QuestionVraag 2

A column of daily counts loads with type object, and one cell reads not counted. Which of the three disguises is this, and what did it do?

Een kolom met dagelijkse aantallen laadt met type object, en in één cel staat not counted. Welke van de drie vermommingen is dit, en wat heeft die gedaan?

This describes the first disguise, the honest blank; a word is not marked NaN.Dit beschrijft de eerste vermomming, de eerlijke lege cel; een woord wordt niet als NaN gemarkeerd.

Correct. One word in a column of numbers makes the whole column text, because a column has one type, and isna() sees a word, not a gap.Juist. Eén woord in een kolom met getallen maakt de hele kolom tekst, omdat een kolom één type heeft, en isna() ziet een woord, geen gat.

This describes the third disguise, which keeps the column numeric; here the column became text.Dit beschrijft de derde vermomming, die de kolom numeriek houdt; hier werd de kolom tekst.

QuestionVraag 3

De winkel registreerde 1134 stuks over 55 getelde dagen van de 60. Een assistent draaide fillna(0).mean() en meldde 18.9. De gewone mean() geeft 20.62. Waarom verschillen de twee getallen?

This has it backwards: both totals are 1134; only the count of days differs.Dit is omgekeerd: beide totalen zijn 1134; alleen het aantal dagen verschilt.

Correct. Filling with zero adds nothing to the total of 1134 and adds five days to the divisor, so 1134 over 60 is 18.9 while 1134 over 55 is 20.62.Juist. Opvullen met nul voegt niets toe aan het totaal van 1134 en voegt vijf dagen toe aan de deler, dus 1134 gedeeld door 60 is 18.9 en 1134 gedeeld door 55 is 20.62.

A gap of 1.72 is not rounding.Een verschil van 1.72 is geen afronding.
